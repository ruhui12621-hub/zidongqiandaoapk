# 全局管理模块

应用的账号签到系统按三个层次组织，所有模块共用一份模板。

## 1. 模板

```text
Template: default (唯一)
```

模板负责与平台无关的通用能力：

- 账号注册、账号状态和云端配置同步
- 通用签到执行流程与结果展示
- 华为云函数部署、配置更新和检查
- 日志组、日志流、运行消息及错误信息

不得为 HoYoLAB、米游社国服或森空岛复制模板。平台差异必须由游戏模块提供。

## 2. 游戏模块

游戏模块使用稳定的平台 ID，集中定义凭据类型、解析规则和允许启用的游戏：

| 模块 ID | 平台 | 凭据 | 游戏目录 |
| --- | --- | --- | --- |
| `hoyolab` | HoYoLAB | Cookie | `GameCatalog.hoyolabOs` |
| `miyoushe_cn` | 米游社国服 | Cookie | `GameCatalog.hoyolabCn` |
| `skland` | 森空岛 | Token | `GameCatalog.skland` |

规则入口位于 `GlobalModuleRegistry`。HoYoLAB 与米游社国服的 Cookie 标记、国服域名识别规则从对应模块读取；森空岛 Token 的格式校验也由对应模块提供。登录 Activity 负责承载网页和采集会话，不再自行定义平台凭据字段集合。

## 3. 账号模块

账号基础关联由以下字段组成：

- `id`：应用内部生成的稳定 UUID，不随 Cookie/Token 更新而变化
- `platform`：所属游戏模块 ID
- `platformUserId`：平台侧身份 ID，用于识别和去重，不作为本地关联主键
- `games`：该账号启用的游戏 ID 集合

Cookie 与 Token 不属于账号基础数据。它们继续按内部账号 UUID 存入独立的加密凭据保管箱；云端部署时才由平台模块与模板共同读取、合并对应配置。

## 4. 约束

- 模板只有一个，平台模块只有上述三个。
- 账号选择的游戏必须属于其所属平台的游戏目录。
- 不允许把一个平台的游戏 ID 写入另一个平台的账号。
- 不允许把 Cookie、Token 或 AK/SK 写入账号列表、普通日志或模块展示数据。
- 账号配置仍以华为云函数配置为权威来源；本地账号缓存不取代云端数据。
- 新增平台时增加一个游戏模块及其解析器，不复制模板和账号管理流程。

## 5. 当前实现边界

当前版本已建立模块注册表、统一平台凭据校验入口、账号游戏归属校验，以及 React 全局管理页面。HoYoLAB/米游社国服游戏勾选继续沿用现有云端 YAML 配置；森空岛云函数当前以 Token 列表为配置格式，若要让森空岛游戏勾选真正影响云端执行，还需扩展其函数配置格式和部署合并逻辑，不能只在界面保存一个本地勾选状态。
